# Проверка исправлений по отзыву

Дата проверки: 22.06.2026.

Финальный редактируемый отчёт: `КР_ПиРКСП_ДицельНС_ФИНАЛ.docx`.

## 1. Реферат

**Исправлено.** Перед оглавлением добавлен реферат со сведениями об объёме,
объекте, цели, реализации, практическом результате и подтверждённых результатах
тестирования.

## 2. Внутритекстовые ссылки

**Исправлено.** В тексте присутствуют ссылки `[1]`-`[12]`; каждый источник из
списка литературы используется хотя бы один раз. Ссылки расставлены в разделах
об архитектуре, Twelve-Factor, React, Router, Redux Toolkit, Node.js, Express,
PostgreSQL, Docker/deployment и репозитории.

## 3. Точность архитектуры

**Исправлено.** Отчёт и `docs/ARCHITECTURE.md` описывают фактическую систему как
контейнеризированный модульный монолит, а не микросервисы. Зафиксированы:

- same-origin API по `/api` без `REACT_APP_API_URL` в сборке;
- пять Compose-сервисов, включая одноразовый `release`;
- четыре долгоживущих production-сервиса;
- единственная внешняя точка входа Nginx;
- отсутствие встроенного TLS и автоматического deploy на VPS;
- фактические роли `app.js`, `server.js` и `release.js`.

Устаревшие утверждения про Render, `CORS_ORIGINS`, отдельные публичные frontend
и backend, Supertest и четыре Compose-сервиса удалены. Архитектурная схема и
рисунки 30, 31, 36, 37, 39, 40 заменены актуальными.

## 4. Coverage-guided fuzzing

**Исправлено.** Подключён Jazzer.js 4/libFuzzer. Target
`server/tests/fuzzing/grading.fuzz.js` инструментирует реальную логику оценки,
мутирует произвольные байты, использует corpus и проверяет инварианты.

Фиксированные SQLi/XSS/RBAC payload переименованы в `security API checks` и не
выдаются за фаззинг. Воспроизводимая проверка `npm run fuzz:ci` выполнила 20 000
мутаций: `cov: 53`, `ft: 282`, corpus вырос с 5 до 66 входов; crash и timeout
отсутствуют.

## 5. Deployment-документация

**Исправлено.** `docs/DEPLOYMENT.md` содержит prerequisites, конфигурацию без
секретов, build/release/run, readiness, smoke-check, demo-data boundary,
backup, update, rollback, диагностику и границу GitHub Actions. Отдельно
указано, что TLS и автоматический VPS deploy не реализованы.

## 6. Разделение build/release/run

**Исправлено в коде и проверено тестами.** Runtime backend больше не выполняет
schema sync, изменение `durationSeconds` или инициализацию настроек.

- `src/app.js` только конфигурирует Express;
- `src/server.js` проверяет БД, запускает API и делает graceful shutdown;
- `src/release.js` выполняет одноразовые административные операции;
- Compose требует успешный `release` перед `backend`;
- `release.test.js` и `serverLifecycle.test.js` фиксируют это поведение.

## Результаты проверки

- frontend: 17 suites, 82 tests - пройдено;
- backend: 7 suites, 34 tests - пройдено;
- Jazzer.js: 20 000 runs - пройдено без crash/timeout;
- production frontend build - успешно;
- обе Compose-конфигурации - `docker compose config -q` успешно;
- DOCX ZIP/XML и все внутренние relationships - валидны;
- в отчёте присутствуют рисунки 1-40 и ссылки на источники 1-12.

Полный runtime smoke-check Docker не был повторён 22.06.2026, потому что Docker
daemon на машине выключен; workflow содержит тот же обязательный smoke-check.
